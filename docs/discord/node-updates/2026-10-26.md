# node-updates - October 26, 2026

## LaMat — 2:47 PM UTC

**2.1.0.25.103 — operator notes**
### Required
- Upgrade node and qclient promptly: this release carries security fixes. Some take effect only when a later release sets their activation frames.
- Upgrade every node (master and workers) before GLOBAL frame 943,200. From epoch 1311 (frame 943,920) storage proofs switch from KZG to post-quantum hash proofs, and registrations for that epoch start at 943,200; an older build does not follow the switch. (#899)

## LaMat — 7:12 PM UTC

**2.1.0.25.104 — operator notes

Required actions**

- Upgrade before GLOBAL frame 943,920 (epoch 1311, about Oct 27 15:00 UTC at the current frame rate): several consensus rules switch on at that frame. Nodes still on an older release then lose gossip with upgraded ones (stricter peer info checks) and cannot follow GLOBAL.
- qclient prover update needs the new qclient from that epoch (it signs the frame).
- NodeService (8337) now listens on loopback only, even if listenGrpcMultiaddr names another address; set listenGrpcAllowRemote: true to keep remote access (and protect it yourself). Log: warn at startup naming the fallback.
