# Community Recap — #general

**October 9, 2026** | 12:00 AM UTC – 12:10 PM UTC

## Network Progress Toward .25 Release

The community discussed the current state of the network as it moves toward the .25 release. Cassie [LEAD DEV] confirmed that "pretty massive progress" has been made, with some shards now earning rewards while others are not yet active, though the reasons are understood. Nodes running the week-old .25 build are ignored by consensus—they remain represented in the shard set but peers won't engage with them, resulting in timeouts. Cassie clarified that these nodes don't get removed from shards but are simply not engaged with.

Several users reported their nodes starting to generate rewards, with one noting all three of their online nodes were earning. The general sentiment was that the network is close to being fully operational.

## Seniority Loss After Reboot

Multiple users reported losing pre-2.1 seniority after rebooting or going offline for over an hour. One user's node dropped from ~7M seniority to ~30k after reboots. stevesweerto provided a detailed explanation: the old .25 build gets ignored by consensus, and the "Joining / Execution Blocked" state with active_shards=0 is expected while shard data replication catches up network-wide. Cassie offered to investigate a specific user's peer ID/prover address if they DM'd her. The consensus was that seniority at 0 is a symptom of shards not yet activating, and it should start accruing once they do.

## Quantum Resistance Discussion

A user asked whether Quilibrium is quantum computer resistant, sparking discussion about quantum threats to crypto. Some noted that quantum FUD has been a significant concern for Bitcoin this year. Finn❄❄❄ remarked that Quilibrium is "at the cutting edge of being quantum resistant." The conversation touched on whether quantum computers could realistically break current encryption before mainnet launch.

## Node Troubleshooting

Mr.Quil reported their node stuck at frame 869800 with 0 active shards and 15 pending joins, receiving errors about the node's key not being in the active set. stevesweerto pointed out that the answer was already available in the channel—the old build issue and replication throttling. Cassie noted that archives are being worked on, and the mutual replication effort between peers in the same shard should speed up the healing process in the next version.
