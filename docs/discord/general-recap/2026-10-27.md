# Community Recap — #general

**October 27, 2026** | 1:09 AM UTC – 11:09 AM UTC

## Shard Production Stall — Cause Found and Fix Ready

Black Swan identified the root cause of the ongoing app-shard production stall: a bug in fix `6c69a72c` (the leaders' frame-body gate). The gate waited on the archive's busy ingest lock, so most proposals carried no shard headers. A shard more than 128 frames behind GLOBAL could never pass the gate again, and archive restarts wouldn't clear it. The issue also blocked committee handoffs after the 06:12 UTC epoch boundary, stopping most shards from producing (14 of 15 on Black Swan's node).

Fix PR #1004 (archives only, any order, no activation) was reproduced and fixed in a test, with a local devnet run in progress. Devnet tests succeeded and the fix is ready for deployment. Community members are waiting for Cassie to bump the branch to .106.

## Legacy Token Recovery via qclient

In response to a question about recovering Quil assets from the 2.0 era, Cassie confirmed that qclient handles this — no separate app is needed this time. Black Swan provided detailed instructions:

- Never upload `config.yml` or `keys.yml` anywhere; `config.yml` holds the private key that owns the coins.
- To read what an old identity holds: create a new folder with a `.config` subfolder, copy the old `config.yml` and `keys.yml` into it, then run `qclient token legacy --config .config --read-rpc /ip4/127.0.0.1/tcp/8337` through a running 2.1 node. This only reads; nothing is moved.
- The last line is the unshielded total in base units: divide by 8,000,000,000 for QUIL.
- Moving coins into a 2.1 wallet is `qclient token shield-all`. Mainnet accepts it only from frame 943,920 (~15:45 UTC today). Tested steps will be posted after the team shields their own coins.
- The public RPC (rpc.quilibrium.com) doesn't resolve right now, so a running node is required.

## Seniority Recovery After Prover Key Change (Issue #856)

Black Swan posted instructions for operators whose seniority dropped after their node got a new prover key (e.g., keys.yml regenerated or replaced). From GLOBAL frame 946,080 (~23:00–23:30 UTC today), the node can move seniority to the current prover:

1. Run 2.1.0.25.106.
2. Stop anything still running with the previous prover key (needs two epochs of inactivity, ~5 hours).
3. Check with `qclient node prover merge --dry-run .config` (reads only). If config.yml was also replaced, add the old config folder by full path.
4. From frame 946,080 the node submits the move automatically.
