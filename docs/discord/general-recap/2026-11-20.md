# Community Recap — #general

**November 20, 2026** | 12:01 AM UTC – 2:34 PM UTC

## From Cassie

Cassie addressed several technical topics today:

- **QStorage**: Confirmed it's used by a decent number of people and companies, with an S3-compatible API. She explained that free hosting requires approval because it gets abused instantly, and offered to help a user directly via DM.

- **Dynamic applications and relational data**: Corrected a user who claimed these weren't available, noting they already exist on Quilibrium via the hypergraph. She linked to the source code for the two entry points for deploying applications and hypergraph namespaces.

- **Code deployment and execution model**: Engaged in a lengthy technical Q&A about the compute intrinsic. Key clarifications: deployment is by-caller (CREATE-like, content-derived address), execution is permissionless for anyone willing to pay, and the write key controls adding code to existing namespaces. She explained the MPC execution model using Privy as an analogy — the namespace owner is the finalizer, the user is the invoker. Inputs stay on each party's side while results surface to both. She noted the code intrinsic will gain more functionality in 2.1.1.

- **Quorum Mobile update**: The API work for migrating old spaces/DMs from non-PQC to coppice is done, as is the shareable coppice library. They're working through UI migration friction — the plan is a small OTA for React Native to detect upgraded spaces/DMs and direct users to install the new version, with automated migration on the new build.

- **Subpatch numbering**: Confirmed 2.1.0.26 subpatches will start from 0.

## Node Operations

Black Swan confirmed that experimental binaries for 2.1.0.26 subpatch 0 are being prepared, which will absorb merged PRs. Binaries will be hosted at the quil-release-binaries repo. Oumlaut reported node metrics from a nine-worker M4 setup: 273 GB written, 2.85 TB read, ~10.5 GB memory, 19.95 GB swap used, with claimable rewards around 0.847 QUIL.

## Network Discussion

A user asked about compressing data packets between nodes, noting throughput issues when validation requires historical global frames from archive nodes with repeated timeouts. This was flagged for consideration.

Another user asked about upgrading from 2.1.0.24 to 2.1.0.25, noting Peer ID and Prover Address changes. Mr.Franc confirmed .24 is incompatible with .25 and that running .24 nodes isn't doing much — .25 introduced many changes including new prover keys.
