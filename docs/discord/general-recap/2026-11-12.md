## Node Performance & Disk Write Optimization
Black Swan shared detailed analysis of node disk write patterns after 10 epochs under the new regime:
- Per-seat writes are ~30 GB/day, matching the expected figure, but still 3.5–5x the budget for a 220 TBW drive's lifetime.
- The main culprit: at each epoch boundary, nodes compact the old-epoch replica range, rewriting ~20–42 GB per epoch while freeing almost nothing (0.7–1.5 GB). This accounts for roughly half of total writes.
- Black Swan is writing a fix to compact only when there is real garbage to free, and will post a build for testing.
- Labels are no longer rewritten every epoch (0 MB on both nodes), so RAM storage isn't viable. Coarser re-encoding would write more, not less.

## Release v2.1.0.25.119
Black Swan released a subpatch with release notes and binaries:
- https://github.com/blacks1ne/quil-release-binaries/releases/tag/v2.1.0.25.119
- The update addresses slow-pace pauses: the node now only pauses when GLOBAL actually stops (head unchanged for 2 min), so the previous "PAUSED" messages from qclient .115 or older will disappear after updating.
- The rollout is timed so node operators have sufficient time to update before the app shard blockage release expected in epoch 1484.
