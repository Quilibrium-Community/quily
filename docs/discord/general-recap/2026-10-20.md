Cassie asked about GitHub merge conflicts with stacked PRs. Black Swan explained the issue: squash merging plus stacks from a fork causes conflicts because a stacked PR carries its parent's original commits, which never reach the base after the parent is squashed. Two workarounds were suggested: squash-merge only the top PR of a stack (which contains all parents), or rebase children onto the new tip. Black Swan will note "merging this merges #N" in top PRs going forward.

TawaFiF reported that v2.1.0.25 no longer builds since #598 due to a missing `ClockStore` trait import in `worker_manager.rs`. Cassie fixed it and updated .25.
