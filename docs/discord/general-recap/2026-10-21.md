## Network Health Progress

Black Swan provided a network health update: **50/103 app shards were producing frames**, later improving to **60/103**. The community discussed what "ready" means for mainnet — Black Swan noted that reaching 100% app shard health would be a major milestone to reassess remaining blockers, but emphasized that *consistently staying* at 100% over an extended period is even better than a single snapshot, since the denominator changes with shard splits/merges.

Black Swan is reviewing PRs including #843 and #844 (node diagnostic reporting fixes) and requested a review of a quilscan-agent PR that simplifies enabling diagnostic data access. He plans to produce multiple PRs today now that log access is available.

## Seniority Loss Investigation

Black Swan wrote up **issue #856** documenting a mechanism where three node operators lost pre-mainnet seniority, with merges being silently refused. Guru_Meditation provided a useful control case: their two recovered nodes (regenerated keys.yml, new prover addresses whose old Ed448 keys never joined post-mainnet) saw seniority merge fine — 404,797 → 754,907 and 790,727 → 995,667.

Black Swan confirmed the code credit each pre-mainnet Ed448 key **once**, to the first prover joining with it since the last network reset. The lost cases had already been credited to their old prover address, then changed keys. He advised backing up each new node's `keys.yml` before first join and using each pre-mainnet config in only one node.

On consolidation questions: Black Swan recommended waiting on seniority merges until network health issues are addressed, and confirmed that once the token app is live, coins can be transferred with qclient + keys.yml alone without starting nodes.

## Security Notes
