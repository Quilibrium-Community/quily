# Community Recap — #general

**November 3, 2026** | 12:54 AM UTC – 11:18 PM UTC

## From Cassie

Cassie provided a high-level update on development activity:
- Work is focused on addressing user reports and network behaviors causing local slowdowns on some shards
- The **coppice spec** now has a functional Rust implementation, sped up because several hypersnap clients want to be DM-compatible with Quorum. Repo: https://github.com/QuilibriumNetwork/coppice-research
- A **megarpc update** is inbound to support Q transactions without needing to run a local node for privacy
- Following that, rollout of qns/qbilling (Q web services)/quorum updates to use it

Cassie also noted that Vitalik has been known to the project for a while — he used early farcaster builds (sent as sideloadable APKs since his phone was degoogled) and generally prefers staying out of protocol debates outside Ethereum. She hinted that Firefly (which Vitalik casts on) will soon have to choose a fork to support, and noted that Firefly hit a "compute credits" issue with old Neynar APIs — she pinged Suji to let them know hypersnap provides those APIs for free.

## Node Operator Notes

**Black Swan** shared an operator note: if your node config sets `engine.archiveEndpoints`, list only archive nodes — regular nodes propose no GLOBAL frames, so messages sent to them are never included even though the node answers "accepted."

**Disk filling issue on 2.1.0.25 nodes:** Worker stores keep deleted storage-proof data on disk until restart; a fix is in progress. Workaround: free a few GB, restart the node service, and deleted data drops within ~3 hours (freed ~11 GB on a 15-worker node). Restart every 2-3 days if free space stays under 20%. Do not delete anything under `.config/store`, `.config/worker-store`, or `storage-labels`.

## Release Status

Black Swan clarified what's holding back the .25 release:
- **Non-consensus issues** (resource usage, logging, operator features) are cheap to test
- **Consensus issues** (how archive and regular nodes agree at scale) require simulating multiple nodes via devnet — more compute and time
- 53 recently filed PRs are almost all merge-ready; Cassie merges Ready PRs into the v2.1.0.25 branch and triggers subpatch bumps
- Several more subpatch bumps expected before mainnet is called quasi-stable

## Qclient Updates

- **Aza** hit errors when trying to shield coins from old configs. Black Swan confirmed it's a qclient bug fixed in .114: qclient read the node's keystore instead of the old config's, and old keystores lack the q-onion-key (now created on first use). A `--recipient` option is also waiting to merge, allowing shielding straight into a main wallet.
- **Black Swan's dashboard** (via `qclient node manage`) shows node KPIs; rewards estimates are included in the .113 binary. Binaries: https://github.com/blacks1ne/quil-release-binaries
