# Community Recap — #general

**October 6, 2026** | 3:13 AM UTC – 12:23 PM UTC

## Network Progress and Reward Distribution

The Quilibrium network made significant strides today as the v2.1.0.25 update rolled out. Cassie confirmed she isolated the reward issue and pushed the .25 update early in the day, with a follow-up update later to resolve frame speed and superfluous messages.

Community member Black Swan provided detailed technical observations throughout the day:
- GLOBAL frames advanced to 861870, with fourteen worker committee-session hosts starting
- All 15 workers initially reported 0 B storage, but partial app-shard progress emerged later (two workers advanced materialized heights from 56→65 and 36→43)
- First mintable rewards began flowing — claimable prover rewards increased from 0.000059358375 QUIL to 0.000118718625 QUIL, with other users reporting similar balances
- Workers encountered "local state differs from the predecessor's sealed checkpoint" errors, with archive bootstrap attempts hitting `ResourceExhausted: forest read workers busy`

Cassie confirmed the consensus errors ("app committee session unavailable: first session not authorized yet") are expected — the network is waiting for archives to reach a target epoch (frame 861840) where consensus set data is agreed upon before restarting with new prover set logic mid-epoch.

## Build Issue and Fix

stevesweerto reported that the tip of v2.1.0.25 (commit 6451b5e) failed to compile — the code referenced gRPC messages/RPCs (`SubmitWorkerProverMessage`, `GetHistoricalCommittees`) not defined in protobufs/global.proto. Cassie acknowledged and added the missing proto definitions. stevesweerto also suggested adding an AGENTS.md file to the repo to help AI tooling flag such issues faster, offering to draft one based on their experience running nodes across a fleet.

## Token Balance and Minting

Black Swan shared that `qclient token balance` now shows claimable prover rewards, referencing PR #697. However, minted balance queries returned an error ("no node serving application... answered this node"), and all five archives rejected `ListShardCoins` with "coin scan: no root in snapshot" — filed as issue #698. Black Swan asked whether this depends on the token app deployment or incomplete app shards.

## Security Advisory

Cassie urged Mac users to update their OS immediately, citing a "mega bad OSX vulnerability" in the latest update that is "actively being exploited."

## From Cassie

Cassie confirmed the reward issue was isolated and fixed, pushed two .25 updates, explained the expected consensus errors as intentional (waiting for target epoch agreement between archives and provers), and noted "those three weeks for the last major changeset was worth it." She also issued the urgent Mac security warning.
